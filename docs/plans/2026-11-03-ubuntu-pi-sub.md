# Brief: move the `ubuntu` branch onto pi-sub

For the agent that fixes the `ubuntu` branch (the ThinkPad running Ubuntu 24.04). Written
on 2026-11-03 on the Mac from `main` at `b29babb` and `origin/ubuntu` at `801635e`.

## Goal

Delegation on Ubuntu runs on our own extension, `pi/extensions/pi-sub`, the same as on the
Mac, and nothing on the branch still uses the npm `pi-subagents` package. Both machines
then have one subagent runtime, one tool API in the prompts, and one set of docs.

## Why the branch is on the npm package

`ubuntu` forked from `main` on 2025-11-10 and imported `main`'s portable config in
October 2026, while `main` was mid-transition. At that moment `pi/README.md` and
`pi/agents.test.mjs` still required `pi-subagents@0.76.0`, but `pi/settings.json` had
already dropped it (`9d158cb`, 2026-10-08). `docs/plans/ubuntu-main-migration.md` step 4
resolved that by re-declaring the pinned package. After that, `main` finished
`pi-sub` and deleted the old runtime, its tests and the pin. Ubuntu is the one behind.

## Read first (on `origin/main`)

- `pi/README.md`, section "Delegation": how pi-sub, `session-models` and the role files
  fit together.
- `pi/extensions/pi-sub/README.md`: tools, state dir, wake-up, timeouts, keys.

  model is told about.
- `bin/pi-contract`: the only check that runs a real pi; it fails when a prompt names a

## Current state of `ubuntu` (what is wrong)

- `pi/settings.json` declares `{"source": "npm:pi-subagents@0.76.0", "skills": [], "prompts": []}`
  and a `subagents.modelScope` block (pi-subagents config).
- `pi/extensions/subagent/config.json`, `pi/archive/` (old custom runtime) and
  `pi/agents.test.mjs` exist; `main` deleted all three.
- `pi/APPEND_SYSTEM.md` tells the model to use pi-subagents' `subagent` tool and
  `subagents_enable`.
- `pi/extensions/session-models/` is an older variant that mentions pi-subagents.
- The prompts are mixed. `fix-friction.md`, `start-day.md` and `review-local.md` already
  use pi-sub's API (`subagent({ role, model, task, cwd, label })`, `subagent_result`,
  `[pi-sub]` wake-ups). `orchestrate.md` and `watch-mrs.md` use pi-subagents' API
  (`agent:`, `action: "status" | "stop" | "resume" | "models"`, `workflow: true`). Those
  calls fail under pi-sub.
- `bin/pi-autoupdate` has a "chord guard" (installs `@earendil-works/chord` into pi's
  release tree). It exists only because pi-subagents runs background children as a node
  process with pi's host packages aliased in. pi-sub runs the `pi` binary itself
  (`run.mjs` spawns `$PI_SUB_PI_BIN ?? "pi"`), so it should not need chord. Confirm by
  reading `launch.ts` and `run.mjs` before deleting the guard.
- `pi/agents/` holds hand-copied team agents. On `main` they are generated by
  `pi/gen/pi_agents.py` (through `plink`) from `~/projects/claude-components`, with the
  header pi-sub expects. `planner.md` and `researcher.md` were removed from `ubuntu` but
  are pi-sub roles named in `APPEND_SYSTEM.md`.
- Also missing compared to `main`: `pi/extensions/recap`, `session-summary`, `claude-hooks`,
  `pi/gen/`, `pi/billion-context.json`. Only take them if the user asks; they are not part
  of this task, except `pi/gen` if you use it for the agents.

## Steps

1. **Check the one known portability gap first.** `pi-sub/runtime.ts` (`defaultPs`) runs
   `ps -E -p <pid> -o command=` and looks for `PI_SUB_ID=<id>` in the output, to make sure
   a pid is really our agent before signalling it. `-E` is a BSD/macOS flag. Hypothesis
   (not verified here): procps `ps` on Ubuntu rejects it. Then `ownsPid` is always false,
   `stop()` throws, and neither `/agents` stop nor the `max_minutes` timeout can kill an
   agent. Run `ps -E -p $$ -o command=` on Ubuntu. If it fails, read
   `/proc/<pid>/environ` (NUL-separated) on Linux and keep `ps -E` on Darwin. `PsRunner`
   is injectable, so add a test for it. Make this change so `main` can take the same
   commit: it is shared code, not an Ubuntu fork.
2. Branch from `ubuntu` in a worktree (`wt add dotfiles <name> ubuntu`). Never merge
   `main` into `ubuntu` or the reverse. `main` deletes Ubuntu's Linux setup and
   `ubuntu` deletes the Mac's.
3. Take from `origin/main` (`git checkout origin/main -- <path>`), then diff each against
   the previous `ubuntu` version and re-apply any Linux-specific edit:
   `pi/extensions/pi-sub/`, `pi/extensions/session-models/`, `pi/APPEND_SYSTEM.md` (keep
   the `<daily_run_state>` paragraph; Ubuntu's `daily` extension injects it),
   `pi/model-selection.md`, `pi/prompts/orchestrate.md`, `pi/prompts/watch-mrs.md`.
   Check the other prompts for any pi-subagents call: `rg -n 'action: "|agent:|workflow: true|subagents_enable' pi/`.
4. Remove the pi-subagents object and the `subagents.modelScope` block from
   `pi/settings.json`. Also delete `pi/extensions/subagent/`, `pi/archive/` and
   `pi/agents.test.mjs`, then the chord guard in `bin/pi-autoupdate` and its tests (after
   the check in "Current state"). Add `pi-sub` wherever `bin/plink`/`install.sh` list
   the extensions, if they list them. Install the package removal on the machine
   (`pi remove npm:pi-subagents` or `pi update --extensions`) and delete the stale
   `~/.pi/agent/pi-subagents/` state folder. Never load both runtimes together.
5. Role files: every role pi-sub launches must exist in `~/.pi/agent/agents/` with the
   pi-sub header (`tools:` allowlist). Either port `pi/gen/` from `main` and let `plink`
   generate the team agents (needs `~/projects/claude-components` cloned), or add the
   header to the hand-copied files. Restore `planner.md` and `researcher.md` from `main`.
6. Keep what `ubuntu` does better: `settings.json` as a per-host seed in `bin/plink` and
   `install.sh` (pi writes `lastChangelogVersion`, `extensionChangelogVersions` and
   `deviceId` into it). `main` should take this too, but not in this task. Note that
   `ubuntu`'s `plink` uses GNU `readlink -m`, which macOS lacks. Keep the Linux daily wake
   port and the other Ubuntu adaptations.
7. Update `pi/README.md` on `ubuntu`. Its Delegation section and the pinned-package
   paragraphs become `main`'s text, with the Linux differences.
